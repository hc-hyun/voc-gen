# 모델 출시일 기준 가상 날짜 정책

문서 버전: 2026-07-26

`source_date`와 `tested_at`은 파일을 만든 실제 시각이 아니라, 합성 레코드가
업무상 발생한 것으로 가정하는 가상 날짜다. 실제 생성 시각은 데이터
매니페스트의 `generated_at`에 별도로 기록한다.

## 날짜 범위

| 데이터 유형 | 가상 날짜 필드 | 허용 범위 |
|---|---|---|
| 내부 개발 테스트 | `tested_at` | 모델 `release_date`의 1년 전부터 출시 전날까지 |
| 시장 VoC | `source_date` | 모델 `release_date`부터 1년 뒤 같은 날짜까지 |

예를 들어 출시 기준일이 `2025-02-07`인 Galaxy S25는 내부 테스트가
`2024-02-07`~`2025-02-06`, 시장 VoC가
`2025-02-07`~`2026-02-07` 범위에 들어간다.

스마트폰 모델이 적용되지 않는 워치·버즈·서비스 VoC는 기존 profile의
`date_start`~`date_end`를 fallback 기간으로 사용하고, 원문 앞에 접수일을
표시해 같은 문구가 서로 다른 날짜에 접수된 경우도 구분한다.

## 초기 집중 분포

균등분포 대신 Beta 분포를 사용한다. 기본값은 다음과 같다.

```json
{
  "mode": "release_relative",
  "window_years": 1,
  "early_weight_alpha": 1.25,
  "early_weight_beta": 3.5
}
```

- 내부 테스트는 개발 기간의 시작, 즉 출시 약 1년 전 쪽에 더 많이 배치한다.
- VoC는 출시 직후 쪽에 더 많이 배치한다.
- 같은 profile, seed, sequence, 모델이면 날짜도 항상 동일하게 재현된다.

검증기는 모든 모델 적용 레코드의 날짜 범위를 건별로 검사한다. 100건 이상의
표본에서는 첫 1/4 구간의 레코드 수가 마지막 1/4 구간보다 많은지도 검사한다.

## 출시 기준일

모델 카탈로그의 `release_date`는 날짜 생성용 정규화 기준일이다. 전 세계
판매일이 서로 다르면 공식 자료에서 확인되는 대표 시장의 일반 판매일을
사용한다. 아직 일반 판매 전인 공개 모델은 공식 발표에 명시된 예정 일반
판매일을 사용한다.

이 기준일은 다음 위치에 함께 남겨 추적할 수 있다.

- 내부 테스트: `device_model_context.release_date`
- VoC: generation sidecar의 `model_context.release_date`

모델 카탈로그와 날짜 정책을 바꾸면 생성 spec hash가 달라지므로, 이전 review,
approval, 데이터 파일을 그대로 재사용할 수 없다.
